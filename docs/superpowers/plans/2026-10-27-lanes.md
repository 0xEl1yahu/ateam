# Lanes and Conflict Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Contracts of a plan that overlap in declared paths or depend on each other run one after another in one shared worktree (a lane); lanes run in parallel; a merge conflict that still happens is recovered by one rebase BUILD instead of stranding the plan.

**Architecture:** Lanes are a pure function of the plan's contracts and the target's files, computed in `ateam.scheduler`. The main loop keeps one thread per contract: `_startable` lets a contract start only when the contract before it in its lane is integrated, so lanes serialise themselves and `max_workers` bounds the lanes running at once. `ateam.worktrees.contract_worktree` resolves a lane follower to its lane's worktree with the predecessor's verified head as base, and records both. On a merge conflict, `ateam.retry` decides between a rebase BUILD and a pause; the scheduler merges the integration tip into the contract's own worktree (markers left), moves the contract `verified -> building`, and runs one BUILD, TEST and verify with no retry.

**Tech Stack:** Python 3.14, click, SQLite state store, git worktrees, pytest with pytest-xdist.

**Spec:** `docs/superpowers/specs/2026-10-27-lanes-design.md` (owner decisions 1-5, owner rulings 6-9). Also binding: `CLAUDE.md`, `docs/superpowers/specs/2026-10-24-ateam-harness-design.md`, `docs/superpowers/specs/2026-10-26-pause-resume-design.md`.

## Review Focus

1. **A re-run after an interruption mid-lane.** The follower's worktree and base must come from the recorded `lane:`/`base:` keys, never be recomputed. Test in Task 2 (`test_a_follower_reuses_its_recorded_lane_and_base`).
2. **A crash between the rebase's intent commit and its store transition.** The file says `building` and the store says `verified`. Today `reconcile_contracts` refuses that; with a `rebase:` key recorded it must complete the store step. Test in Task 4.
3. **The rebase BUILD ends without concluding the merge** (MERGE_HEAD still present, or HEAD does not contain the tip). Verify must not run on that tree; the plan pauses `environment_failure` as a conflict. Test in Task 5.
4. **A conflict pause is resumed after the integration tip moved again.** The rebase must merge the current tip, not the one recorded in the earlier window, unless a merge is still in progress; the post-BUILD check uses `rebase:<cid>.tip`, never the live tip. Test in Task 6 (`test_resume_after_the_tip_moved_rebases_onto_the_new_tip`).
6. **A crash after `rebase:` is written but before the contract moves to `building`.** The re-run must run the rebase BUILD, not pause with "again after its rebase BUILD". Test in Task 5.
7. **A contract cut before this change, resumed after it.** It has `base:` and work in `worktrees/<cid>` but no `lane:`; it must stay there. Test in Task 2.
5. **Two contracts whose globs overlap only through a file that does not exist yet** (`src/x/new.py` declared literally by one, `src/x/**` by the other). They must share a lane. Test row in Task 1.

- Produces: `decide_conflict(rebased_this_window: bool, build_attempts_used: int, attempts_allowed: int, uneditable: list[str]) -> Decision` in `ateam.retry`: `Decision("pause", "", "environment_failure")` when `uneditable` (conflicting paths outside the contract's `paths`, owner ruling 12) is non-empty, when rebased this window, or when no attempt is left; otherwise `Decision("rebase", tier="", reason=None)`. - Produces: `rebased_this_window(db, cid) -> bool` in `ateam.worktrees` (the predicate in Global Constraints).
- Produces: `prepare_rebase(paths, db, owner, plan_id, cid, tip: str) -> tuple[ContractWorktree, list[str]]` in `ateam.worktrees`, in the contract's worktree (`worktree_path`):
  - a merge in progress whose `MERGE_HEAD` equals `rebase:<cid>.tip`: leave it, set `base:<cid>` to that tip if it is not already, return the unmerged paths;

Idempotent: a step already done is skipped.
- Produces: `reconcile_contracts` completes the store when the file says `building`, the store says `verified`, `rebase:<cid>.window == db.window_start(cid)`, and the contract's worktree shows that rebase (`MERGE_HEAD == rebase.tip`, or `rebase.tip` an ancestor of HEAD): `db.transition("contract", cid, "building", by="run", reason="reconciled after an interruption (rebase)")`. Any other mismatch still raises.
